# Product Requirements

What a capability must do and who needs it, written as a narrative, with a `## Stories` table of the tracker issues that deliver it.

Acceptance criteria never appear here. They belong on the story, where they can be checked off; a requirement that carries its own checklist drifts from the tracker. Link the issue instead.

Not here: why a choice was made (that is a Decision), an open investigation (that is Research), or how something works today (that is a Specification).
